# @context/database

Схема PostgreSQL, роли, RLS и доступ приложения к данным.

## Источник истины — SQL

Структура задаётся файлами `migrations/*.sql`. Только там выражаются вещи, которые
Prisma не описывает: `ROW LEVEL SECURITY` и `FORCE ROW LEVEL SECURITY`, политики,
композитные внешние ключи вида `(organization_id, id)`, частичные уникальные индексы,
роли БД и права, `SECURITY DEFINER` резолверы контекста.

`prisma/schema.prisma` **получен интроспекцией** и вручную не проектируется:

```sh
npm run db:migrate                  # применить новые SQL-миграции
npx prisma db pull --config prisma.config.ts   # обновить модель по фактической схеме
npm run db:generate                 # сгенерировать клиент
```

Миграции неизменяемы: изменённый файл, который уже применён, скрипт отвергнет по
контрольной сумме. Исправление — всегда новый файл.

## Переименованные связи

Интроспекция даёт связям машинные имена вида
`users_access_grants_approved_byTousers`. В схеме они переименованы вручную
(`approver`, `grantee`, `requester`, `extends_grant_same_org`, `extensions_same_org`,
`versions`, `current_published_version` и т. п.).
Цепочку продлений держит только композитный ключ `(organization_id, extends_grant_id)`:
одиночный FK на `extends_grant_id` снят миграцией 0015, поэтому связей
`extends_grant`/`extensions` в схеме больше нет.
Prisma сохраняет такие переименования при повторной интроспекции — восстанавливать их
после `db pull` не нужно. Если после обновления схемы в коде появились длинные
машинные имена, значит связь новая: переименуйте её так же и обновите этот список.

## Роли

| Роль | Назначение | Чего не может |
|---|---|---|
| `context_owner` | Миграции, владение объектами | В production не должна иметь `BYPASSRLS` |
| `context_api` | Работа кабинета и участника | Нет доступа к схеме `evaluation` |
| `context_worker` | Подсчёт и подготовка заключений | Нет доступа к `identity` и `evaluation` |
| `context_evaluator` | Исходы исследования и сравнение | Нет доступа к `core.answers` и заключениям |

Пароли ролей задаёт окружение (`DB_PASSWORD_*`); в SQL их нет.

## Контекст организации

Любая работа с данными tenant идёт через `withTenant(prisma, { organizationId }, …)`.
Он открывает транзакцию и ставит `set_config('app.organization_id', …, true)` —
именно transaction-local, иначе контекст остался бы следующему запросу на том же
соединении пула. Отсутствие контекста означает отказ, а не полный доступ.

`withPlatformOps` — эксплуатационный режим администратора платформы: метаданные
организаций и техническое состояние. Ответы участников, evidence и заключения им
не открываются: на этих таблицах политика строгая.
